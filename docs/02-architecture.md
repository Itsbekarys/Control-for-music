# Как работает вся цепочка

## Windows-агент

Агент собирает состояние Windows и приложений и отправляет JSON на сервер. Основная точка приёма:

```http
POST /api/heartbeat
Authorization: Bearer <ключ конкретного компьютера>
Content-Type: application/json
```

Пример тела ниже искусственный. Поля соответствуют доступному серверному коду:

```json
{
  "hostname": "SHOP-PC-01",
  "audio_device_active": true,
  "audio_muted": false,
  "audio_volume_percent": 35,
  "vlc_running": true,
  "vlc_state": "playing",
  "vlc_volume_percent": 68,
  "audio_sources": [
    {
      "program": "vlc",
      "active": true,
      "signal_detected": true,
      "muted": false,
      "volume_percent": 68
    }
  ],
  "history_tick": false
}
```

На сервере я проверяю Bearer-токен, соответствие hostname, типы и диапазоны полей. Случайный клиент не должен иметь возможность приписать свои показатели другому компьютеру.

Сервер хранит SHA-256-хеши токенов, а не использует hostname как единственный способ авторизации. Для этого нужен случайный длинный токен: один хеш слабого пароля нормальную защиту не даёт.

`last_seen` обновляется при приёме отчёта сервером. Поэтому для оценки доступности важен серверный момент приёма. Время на Windows всё равно стоит держать правильным: оно влияет на диагностику, TLS и другие функции системы.

Проверка схемы нужна ещё и против кривых данных: отрицательная громкость, строка вместо boolean или слишком большой список сессий должны отклоняться.

## Расширение Edge

Расширение дополняет агент данными о доменах вкладок со звуком:

```http
POST /api/audio-tabs
Authorization: Bearer <отдельный ключ расширения>
Content-Type: application/json
```

```json
{
  "hostname": "SHOP-PC-01",
  "domains": ["radio.example.com"]
}
```

Ключ расширения сверяется с `audio_token_hash`, основной ключ агента с `token_hash`. В доступном коде список доменов ограничен десятью элементами и дополнительно валидируется.

Для панели важна свежесть данных расширения. Домен, присланный вчера, нельзя выдавать за источник звука прямо сейчас. Отдельно различаю свежий пустой список и отсутствие свежего отчёта.

Браузер сообщает признак звука вкладки, а не измеряет акустику зала. И закрытый Edge не обязан присылать новые данные.

## Серверные компоненты

| Компонент | За что отвечает |
| --- | --- |
| Nginx | HTTPS и обратное проксирование |
| Waitress | Запуск WSGI-приложения |
| app.py | Веб-приложение, вход, магазины |
| agents.py | Компьютеры, приём heartbeat и аудиодоменов |
| music_status.py | Классификация музыкального состояния |
| connection_monitor.py | Переходы online/offline |
| Фоновый обработчик | Периодические проверки состояния |
| monitor.db | Компьютеры, показатели, политики и события |

Это описание модулей из доступных материалов, а не список файлов, уже включённых в этот репозиторий документации.

Важные таблицы:

* `stores`: магазины.
* `computers`: связь магазина и ПК, хеши токенов, последний отчёт и payload.
* `audible_tabs`: домены и время отчёта расширения.
* `connection_states` и `connection_events`: состояние связи и переходы.
* `music_policy`: расписание и порог тишины.
* `music_status`: рассчитанное состояние ПК.
* `music_history`: история музыкальных состояний.

Поле `history_tick` управляет дополнительным архивированием отчёта в файлы истории. Наличие файлового архива зависит от запросов агента. Базу и файловую историю при резервном копировании учитываю отдельно.

## Как я решаю, есть ли музыкальный сигнал

Алгоритм проверяет несколько условий вместе:

1. Активен ли аудиовыход.
2. Не выключен ли звук Windows и не равна ли системная громкость нулю.
3. Переданы ли данные аудиосессий.
4. Есть ли положительный сигнал у подходящего приложения.
5. Активна ли сессия, не включён ли mute, разрешает ли громкость воспроизведение.

Windows System Sounds, AnyDesk и источник с именем unknown исключены из кандидатов на музыку. При этом любой другой программный сигнал не превращается автоматически в распознанный музыкальный трек: классификатор не занимается распознаванием композиции.

Если данных не хватает, я показываю unknown. Додумывать положительный или отрицательный результат вместо отсутствующей телеметрии нельзя.

## Статусы

| Код | Что означает |
| --- | --- |
| waiting | Ещё не было первого отчёта |
| playing | Обнаружен подходящий сигнал, программный вывод разрешён |
| pending | Неблагополучное состояние пока короче порога |
| silent | Тишина по последовательности наблюдений дольше порога |
| muted | Выключен звук Windows или системная громкость нулевая, порог пройден |
| no_output | Нет активного аудиовыхода, порог пройден |
| unknown | Недостаточно данных или некорректное время |
| stale | Отчёт устарел для оценки тишины |
| offline | Давно нет heartbeat |
| outside | Контроль тишины сейчас вне расписания |

В доступном модуле порог stale начинается после 150 секунд, offline с 300 секунд. Offline проверяется до расписания: отсутствие связи видно и вне рабочего окна.

Расписание по умолчанию: с 09:00 включительно до 22:00, часовой пояс `Asia/Almaty`. Порог тишины в коде по умолчанию 180 секунд. На пилотном сервере при последней зафиксированной проверке было 60 секунд. При обслуживании читаю фактическую `music_policy`, а не ориентируюсь на дефолт.

Неблагополучное состояние сначала попадает в pending. Подтверждение длительности строится по свежим последовательным отчётам. Если пришёл один отчёт о тишине, а потом агент исчез, я не считаю, что он всё это время надёжно измерял тишину.

Смена версии политики, большой разрыв между наблюдениями и переход суток влияют на продолжение счётчика. Это помогает не тащить вчерашнюю тишину в новый рабочий день.

## История и антиспам

Новая запись появляется при смене состояния. Смена источника при playing тоже может создать событие. Одинаковое состояние на каждом цикле не должно превращаться в сотни одинаковых записей.

```text
playing -> pending -> silent -> playing
```

Так я вижу переходы и могу восстановить последовательность. При этом история программных наблюдений не равна непрерывной записи звука.

## Что может дать ложное ощущение исправности

* VLC открыт, но поставлен на паузу.
* Syncthing работает, но плеер не запущен.
* Браузер сообщает домен, но его данные уже устарели.
* Агент работает в другой пользовательской сессии и не видит нужные аудиосессии.
* Windows выдаёт сигнал, но усилитель или физические колонки выключены.

Поэтому проверяю всю цепочку и не выдаю один технический признак за ответ на все вопросы сразу.
