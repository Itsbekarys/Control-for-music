# Где я остановился

Статус ниже восстановлен по доступным материалам и проверкам до 8 ноября 2026 года. В рамках подготовки этой документации я не подключался заново к рабочему серверу и не менял настройки магазинов.

## Что уже есть

* Сервер Flask/Waitress за Nginx.
* SQLite с магазинами, компьютерами, телеметрией и историей.
* Приём heartbeat Windows-агента.
* Отдельный API аудиодоменов Edge и отдельный ключ расширения.
* Разделы панели для музыки, магазинов, компьютеров, аналитики и истории.
* Классификация музыкального состояния и проверка пропажи связи.
* Фоновый обработчик без отправки новых музыкальных событий в Telegram.
* Исправление определения VLC при округлении громкости аудиосессии до нуля.
* Ежедневные архивы с проверкой целостности и восстановлением копии базы.

## Что подтверждали на пилоте

При предыдущей проверке сервер получал свежие отчёты тестового ПК. Сигнал VLC появился в панели, громкость VLC и Windows отображалась отдельно. Syncthing был запущен, музыкальная папка существовала.

Тогда же были успешно выполнены девять тестов логики музыкального состояния. Они проверяют сигнал, низкую громкость VLC, последовательные отчёты тишины, разрывы связи, расписание, неполную телеметрию, исключение системных звуков и отсутствие повторных событий при неизменном состоянии.

Это результат конкретной предыдущей проверки. Он не подтверждает, что все Windows-сессии, браузеры и будущие версии агента уже испытаны.

У расширения Edge в последней серверной проверке данные были старыми. Значит, его актуальную сквозную работу надо подтвердить повторно, а не считать закрытой задачей только по наличию кода.

## Что ещё проверяю перед масштабированием

| Сценарий | Ожидаемое поведение |
| --- | --- |
| VLC играет и колонки слышны | В панели есть сигнал и корректные показатели |
| VLC на паузе | После последовательных отчётов и порога появляется тишина |
| Включён mute Windows | Сначала pending, затем соответствующее состояние |
| Нет аудиовыхода | Состояние no_output после порога |
| Нет свежих отчётов | stale, затем offline |
| Связь восстановилась | Возврат в актуальное состояние и событие истории |
| Звук идёт из Edge | Свежие аудиосессии и актуальные домены расширения |
| Edge закрыт | Старые домены не показываются как свежие |
| Перезапуск Windows | Агент возвращается в нужной пользовательской сессии |
| Перезапуск VPS | Поднимаются веб-часть, worker и расписание бэкапов |
| Восстановление на другой машине | Работают вход, токены и тестовый агент |

Паузы, mute и отключение устройств проверяю на тестовом ПК или вне рабочего времени. Музыку в действующем магазине ради красивого теста не дёргаю.

## Ближайшие задачи

1. Подтвердить все сценарии на одном тестовом компьютере.
2. Подготовить воспроизводимый установщик агента и расширения.
3. Продумать выдачу, хранение, отзыв и замену ключей.
4. Добавить внешнее хранение бэкапов и испытать полное восстановление.
5. Проверить несколько филиалов с разными сетями и сессиями Windows.
6. Собрать метрики нагрузки и объёма истории.
7. После пилота постепенно расширять парк до 100+ ПК.
8. Отдельно закончить и проверить Docker-развёртывание.

Процент готовности я не считаю технической гарантией. Для меня готовность определяется пройденными сценариями, понятным восстановлением и стабильным пилотом.
